# Design rounds on Upload and Configure

Part of `scaffold-workflow-app`. Read this when the smoke run has passed and you are opening a round.

Run is a log and a button; Results belongs to `build-insight-dashboard`. The other
two are pages the user touches on **every run**, and a generated form is not a
design.

Once the app boots, take Upload then Configure through design rounds. Full round
mechanics are in `build-insight-dashboard`; the parts that matter here:

- Open the page in the **user's browser** before opening a round — literally,
  with `start <url>` on Windows, `open <url>` on macOS, `xdg-open <url>` on
  Linux. This needs no browser tooling: opening a page and driving one are
  different capabilities, and a round that cannot be driven can still be opened.
  Not a
  screenshot described to them — the screenshot is how *you* check the page, and
  saying you took one narrates machinery.
- **Bounded to what the template already does.** These two pages have a shape
  the template chose, not this app. A suggestion is in bounds when it is
  implemented by an argument the template's own widgets already accept — a
  `name`, a `fallback`, a `custom_defaults`, an `advanced` flag, a `help` string,
  a `widget_type` — or by section naming, section order, or a named preset in
  `presets.json` (see `add-presets`). Reaching for a layout primitive the page
  does not already use is out of bounds. *"Drop the tabs, put MS data and the database side by side"* is a good idea
  about the wrong thing.
- **One suggestion at a time**, asked, not listed. Three is a ceiling, not a
  quota — a ceiling on the *round*, and never on one screen. A user handed three
  at once reads a pile rather than a choice. Ask the highest-value one,
  take the answer, then ask the next. Each must point at something visible; offer
  two and name the third clean rather than padding.
- A free field and an exit, always. Check the request against what exists,
  then answer in one of the five shapes — *yes* / *yes and here is what you lose*
  / *not as stated* / *yes but it reopens an earlier stage* / *no, and here is the
  nearest thing*. **Never silently substitute** the nearest possible thing.
- Apply, restart the server, re-render. Streamlit does not re-import an edited
  `src/` module; without the restart you show the user their unchanged page.

| axis | Upload page | Configure page |
|---|---|---|
| **data** | which file types, which are optional, what the labels say | which parameters are visible, in what order, what the help says |
| **layout** | the section names and the order they appear in | section order, and what sits behind *advanced* |
| **behaviour** | what shows with nothing uploaded yet | presets, and what the defaults are |

Two suggestions nearly always right and almost never generated by default:
**order config parameters by measured effect size** — `interview-parameters`
already knows it, and screen order otherwise implies an importance that is not
real — and **save the resolved notebook values as a preset**, a labelled way back
to "what the notebook did". `add-presets` owns the `presets.json` schema; a
preset is also the cheapest in-bounds suggestion a Configure round can make.

Two `DEFAULTS` fields whose defaults are wrong for most parameters, and both fail
silently:

- **`widget_type`** — the legal values are exactly `text`, `textarea`, `number`,
  `selectbox`, `slider`, `checkbox`, `multiselect`, `password`, `auto`
  (`StreamlitUI.py:593`). **Anything else renders nothing at all.** The chain
  that dispatches on it is a run of `elif`s with no final `else`
  (`StreamlitUI.py:678-812`), so an unrecognised value matches no branch, raises
  nothing, warns nothing, and the parameter simply is not on the page. Measured
  on a real build: four widgets declared `number_input` — the Streamlit function
  name, not the value this template takes — and the Configure page came up
  missing four controls with a clean log. Give it explicitly to anything a
  preset should drive.
  `input_widget` prefixes the key (`StreamlitUI.py:676`), then the `auto` branch
  recurses passing that already-prefixed key, prefixing it twice; the preset's
  delete-list computes one prefix (`ParameterManager.py:647`), misses the stale
  session key, and the old value overwrites the preset on the next rerun.
- **`step_size`** — `input_python` defaults it to **1** (`StreamlitUI.py:1367`).
  On a float parameter spanning 0.0–1.0 that is a two-position control, and on a
  tolerance spanning 0.0–5.0 it is six. Declare it for every non-integer
  parameter; the default is only ever right for counts.
