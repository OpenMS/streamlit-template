# The processing step declares its outputs statically

A python tool generated by capture declares `OUTPUTS = [...]` alongside `DEFAULTS`,
naming each file it writes, that file's role, its columns and the identifier it can
be linked on. The dashboard stage reads this declaration without executing anything,
and the generated test asserts that a real run matches it.

## Considered Options

A `manifest.json` written at runtime is always truthful, because the run produces
it — but it forces the ordering "run before you can design", which would make the
dashboard stage unusable until a possibly slow analysis has completed, and would
leave the tutorial unable to design a dashboard until then. Writing only native
OpenMS formats and converting at render time is the most idiomatic option, but
repeats conversion on every rerun and defeats OpenMS-Insight's server-side
pagination, which needs files it can page through. Inferring roles by sniffing
column names leaves nothing for a test to assert against.

## Consequences

The declaration can drift from what the script actually writes. That is deliberate:
the drift is exactly what the generated test detects, and a failure there is a real
defect rather than a stale comment.
